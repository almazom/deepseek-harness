# Session V3 persistence format

English | [中文](v3.zh.md)

## Summary

Inspect the V3 persistence types captured at `dsh-v0.1.5-alpha.1`. The header requires the protected system head: system prompt text left `request/header.data.header.system` for dedicated `system/message` events, PTC dispatch events carry their released names, and the header gained the optional `agentPreset` field. This snapshot retains V3 declarations before the V4 header-origin change.

<a id="characteristics"></a>
## Format characteristics

These facts describe the selected checkpoint. The generated tables below preserve the exact field types and optionality.

- `SessionHeader.version` resolves to the literal 3. The header carries the optional `origin` and `agentPreset` fields; `origin` is closed over the literal `"subagent"`.
- System prompt text travels in `system/message` events anchored to an open step; `request/header.data.header` no longer embeds a `system` member.
- PTC dispatch events are named `tool/ptc-dispatch-start` and `tool/ptc-dispatch`; surface replacement operations use released `startSeq` / `endSeq` endpoints.

The [V3 codec](../../../packages/session/session-format-v2-to-v3/src/codec.ts) owns one-event-per-row framing, range-encoded source references, protected system-head relationships, and inherited cuts derived from `session/end-seed` markers. The [V2-to-V3 specification](../../../packages/session/session-format-v2-to-v3/README.md#v2-to-v3-specification) owns system-message insertion, PTC event names, and canonical envelope conversion.

For a seeded V3 Session, the last `session/end-seed` event carrying `data.inherited: true` identifies the inherited cut by its sequence position. Physical `sourceEventSeqs` may use encoded ranges; the logical schemas retain expanded number arrays.

<a id="verification"></a>
## Verification and limitations

The [source-only extractor](../../../scripts/persistence-schema.ts) ran with TypeScript 6.0.3. Reconstruction omits redundant `object` intersection members and discards normalization-unreachable type definitions; it preserves existing `any` / `unknown` and does not substitute opaque types for unresolved imports. The V3 root digests match the released V3 writer state reconstructed from the published tag.

Historical surface-event declarations permit optional `surfaceOp`. This is retained evidence of declared types, not permission to omit fields required by a codec or migration validator. Opaque values, external plugin events, packed body encoding, and runtime relationships are outside the type inventory’s coverage.

```sh
pnpm run verify-persistence-formats
```

The check validates every format through the current writer, schema completeness, bilingual declarations, and generated tables using only this checkout. It does not replay historical applications or establish migration safety. See the [format index](README.md) for maintenance rules and the [current catalog](../../persistence-catalog.md) for today’s declarations.
