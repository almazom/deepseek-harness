# Agent Note：无头会话来源

Status: implemented

[English](2026-09-17-headless-session-origin.md) | 中文

## 问题

GUI 会话列表无法区分操作者手动打开的会话与一次性无头 runner 创建的会话。无头运行显示为普通行，因此用 `dsh --profile headless` 编写脚本的操作者既看不出哪些行由机器生成，也无法隐藏它们。

## 决策

无头 runner 会在它创建的每个会话上写入持久化 header 来源 `headless`，该取值由[已发布 session-format 迁移](2026-08-31-released-session-format-migrations.zh.md)所述的 released v4 格式边界准入。来源始终是会话数据：创建时一次性写入并保留在日志中，而所有需要对 subagent 会话特殊处理的消费方仍然只判断 `subagent`。

Workspace 浏览器把基于来源的可见性交由用户控制。视图选项中的**显示**入口可在 `all`（默认）、`human`（隐藏无头创建的行）与 `headless`（隐藏人工创建的行）之间选择；筛选一致地作用于分组区块、单列表和搜索——在某一个列表里隐藏某行的筛选必须在所有列表里隐藏它。可见的无头创建行会带本地化徽标。缺失 origin 仍表示人工创建，因此所有既有会话无需迁移即可保持当前可见性。

## 已考虑的替代方案

**在标题前加「Headless:」前缀。** 存储的标题是用户可重命名的数据；用户能删掉、且重命名对话框与标题继承可能保留或弄乱的标记，不构成身份标识。未来每种机器来源还都得再加一个前缀。

**在客户端推断来源。** 证据缺失无法区分无头会话与旧的人工会话，浏览器既会漏行也会误判；只有写入方在创建时知道真相。

## 后果

旧版本构建会把本次改动写入的日志当作未知的 format v4 拒绝，直到它们带上 v4 边界；这是 session-format 升级标准的发布成本。筛选是浏览器视图状态（持久化键升到 `dsh.workspace.view.v6`），不是共享设置，每个浏览器记住自己的选择。无头会话仍可被 runner 直接采用：来源 `headless` 不继承 subagent 的拒绝逻辑。
